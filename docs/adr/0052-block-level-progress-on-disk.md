# ADR 0052：块级进度落盘——重试只补缺失块，缓存不是事实源

- 状态：accepted
- 日期：2026-10-02
- issue：#232（本 ADR 是 #232 的交付物）
- 相关 / 修订：ADR 0047（行预算：预算耗尽后重试是常态）、ADR 0048（模型健康：重试的另一半）、ADR 0031（翻译产物形态：缓存的是**块**，不是产物）、ADR 0009（派生状态不落库）、ADR 0007（净化边界不变）

**新增场景从 **AC-234** 起**（AC-234..235，见 `SCENARIOS.md`）。

## 背景

行级重试从第 1 块重来：一个 12 块的文档在 360s 预算下反复重译前几块、永远走不到结尾（D7）。
#227 之后"预算耗尽"是**主动且可诊断**的路径 ✓，#228 之后坏模型会被冷却降级 ✓ —— 但重试本身
仍然把已经翻译好的块再买一次。

## 决策

1. **运行时给每行一个 scratch 目录**：`<storage_root>/processor-cache/<plugin_id>/<lang>/<item_id>`，
   经 `item_ctx["cache_dir"]` 交给处理器。处理器在**每块成功之后**把该块的译文写进去（临时名 +
   `Path.replace` 原子落位），在翻译下一块之前先查缓存。
   - 键按 **plugin + 语言 + item**：换一门语言是另一个产物，不同行也不该读到彼此的块；**按 item
     而不是按 attempt** —— 重点正是"下一次尝试能找到这一次做完的"。
   - 缓存的是**块**（`_translate_one` 的返回），**不是产物**：重建与净化路径（ADR 0031 / 0007）每次
     都照走，所以产物与一次性完成逐字节一致（AC-234 的断言就是这一点）。
2. **成功后由运行时删掉整个目录，失败时保留**。删除放在 `run_processor` 成功返回之前 —— 只有那里
   同时知道"这一行成功了"和"是哪一行"。
3. **缓存不是事实源**：不建表、不加列、不写 item/enrichment 字段（AC-235）；丢了只是重译。它也不
   参与备份语义（`docs/domain/data-model.md` 已标注为可丢）。
4. **写失败不是失败**：缓存写不进去（只读目录、磁盘满）只记一条 warning，行照旧成功 —— 译文已经在手。
5. **不做块级并发**（明确推迟）：它放大瞬时 QPS 与 provider 并发限制的风险。触发条件：本 ADR 落地后
   仍出现"单行块数导致超时"。

## 后果

- 因为预算耗尽或模型冷却而重试的行**不再从零开始**：已完成的块直接从磁盘回来，进度行标 `(cached)`
  （#230 的通道，可观测）。
- 缓存未命中就是一次 `read_text` 失败（ENOENT）——**不是**错误路径，不需要单独分支。
- **永久失败的行会留下一个小目录**（不会再重试 → 没人清理）。接受它：缓存可丢，而且 `retry_enrichments`
  复活那一行时正好复用。**写明**：不做后台清理器（没有消费者，且会引入一个新的调度面）。
- 缓存目录在 storage 根下，会随备份一起走。因为它可丢，恢复备份时它不一致也无害 —— 同样是写明的取舍。

## 被否决

| 备选 | 否决理由 |
|---|---|
| 把进度/缓存做成表、或写进 item 字段 | 事实源污染；ADR 0009 / 0048 已两次否决同一招，AC-235 也明文禁止 |
| 处理器自己决定缓存位置（env 或默认路径） | 子进程 env allowlist 里没有 `PEARSS_STORAGE_DIR`（它是 host-side），而把存储根塞进每个处理器的凭据前缀会扩大暴露面；由运行时给路径还顺带回答了"谁来清理" |
| 按 attempt / uuid 建目录 | 下一次尝试就找不到它了 —— 而缓存的意义正是跨尝试 |
| 缓存**产物**而不是块 | 产物是"这一版正文 + 这一版块切分"的函数；缓存块让重建与净化每次都跑（边界不变） |
| 成功后保留缓存（"下次更快"） | 没有读者：下一次尝试只在这次失败时发生；留着只是无界增长 |
| 块级并发 | 见决策 5：推迟，附触发条件 |
