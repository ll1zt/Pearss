# ADR 0056：模型降权按一行的失败比例——「答对一块」不再复位

- 状态：accepted
- 日期：2026-10-05
- issue：#268（本 ADR 是 #268 的交付物）
- 相关 / 修订：**部分 supersede** [ADR 0048](0048-model-health-lives-in-the-worker.md) 的决策 3「复位」与决策 4「报告的形状是每模型一条、折叠过」——判定改为按一行的失败**比例**，报告改为按模型计数。ADR 0048 的其余部分（状态在 worker、内存态不落库、策略下行/报告上行的数据通道、冷却的 5→10→20→40→60 分钟与封顶、行内预算 2、永久类只问一次、整链冷却）不变。ADR 0051 的投影形状不变（窗口计数由 #269 另加）。ADR 0017 的签名冻结不受影响：仍是数据字段扩展。

**场景**：AC-256..258（见 `SCENARIOS.md`，归属 #268）。

## 背景

ADR 0048 的两层折叠都把「答对」当成「健康」：

- 处理器侧 `_ModelReport` 是**每模型一个布尔**（答对覆盖答错）；
- worker 侧 `ModelHealth.record` 收到「答对」就 `pop` 掉失败计数与冷却。

而 `_translate_one` 是**按分段**调用的：一行的下一个分段重新从链首走。于是「这一段超时、那一段答对」是常态。实测（#268 的 journal，10 小时窗口）：

| 指标 | 值 |
|---|---|
| `translate model … falling back to …` | 132 |
| 冷却安装 | 12 |
| 涉及主模型 `gemini-3.5-flash-lite` | 114 / 132 |
| 冷却安装明细 | 主模型只有 300s / 600s / 1200s 各一次 |

主模型只要**偶尔答对**，失败计数每次被清零，冷却永远停在 5 分钟地板，爬不到 1 小时上限；5 分钟后它回到队首，再超时一次 —— 与实测的 5–8 分钟循环完全吻合。

这是 ADR 0048 的**盲区**，不是它的缺陷：它修的是 #227 那种「连上但不回」的模型（**从不**答对，能一路升到上限），没有覆盖「时好时坏」。

## 决策

### 1. 报告按模型计数，不再是一个布尔

上行事件从 `(model, error_class | None)` 变为 **`(model, asked, failed, last_error_class | None)`**：这一行向该模型发了多少次请求、其中多少次失败、最后一次失败是什么类。字段仍走 `item_ctx["model_events"]` 这条既有数据通道（ADR 0048 决策 2），键名不变。

### 2. 判定按一行的失败比例

`row_ratio = failed / asked`。三个分支：

- **`failed == 0`** —— 这一行它答上了被问的每一块：**复位**（清冷却、清升级档），下次失败从 5 分钟地板起；
- **`row_ratio >= PEARSS_MODEL_FAILURE_RATIO`（默认 0.5）** —— **降权行**：升级档 +1，冷却 `min(floor × 2^(档-1), 上限)`；
- **其余** —— **抖动**：不冷却、不升级（升级档归零）。

### 3. 冷却的其余规则不变

5→10→20→40→60 分钟与 1 小时上限、行内预算 2、永久类只问一次、整链冷却不发请求 —— 全部沿用 ADR 0048。

## 理由

- **「答对过」不是健康证据**。一个模型在 3 个分段里答对 1 个、超时 2 个，与答对 3 个是不同的事实；把前者折成 `None` 就是把它算作健康。**比例**是「这一行对模型说明了什么」的最小充分统计量。
- **门槛是抖动与慢性半坏的分界**。「九次里错一次」是这一块的事，不该让链最快的模型下去等 5 分钟；「三次里错两次」是这个模型的事。选项 B（本行失败过即计数，不看比例）同样能治好症状，但代价是**一次抖动即吃 300s 冷却**——这正是本 ADR 用比例门槛挡掉的那部分。
- **升级档只在连续降权时推进**，所以「偶发抖动」（低于门槛）不会累积，而「每行都部分失败」会：这正是实测里 5 分钟死循环的直接解药。
- **备选被否决**：
  - **维持现状（可 declined）**：慢性半坏模型永远排在队首，每条白付一次超时（本次 86% 的切换由主模型贡献）。
  - **本行失败过即计数（选项 B）**：见上，抖动代价高。
  - **只有最后一个候选的空补全算瞬时**（只处理症状）：改的是分类而不是降权规则，另一个模型换个失败类又会重演。

## 后果

- 单模型链上，**部分失败**的行现在也会让链冷却 5 分钟（此前只要有答对就不会）——这是「不硬试」的代价沿用到半坏模型上，与 ADR 0048 对全坏模型的处理一致。
- 状态仍**只活在 worker 内存里、不落库、可丢**（ADR 0009/0048）：重启后第一次失败重新付一次学费。
- 报告的字段变宽了，`processor_runtime._collect_events` 的防御性校验随之改为 4 元组；`hooks.py` 的键说明同步。
- 投影面（`model_health` 那一格）在 #269 里补窗口计数，让「10 小时 132 次切换」这种形状**在诊断面上可见**——本 ADR 只改判定规则。

## 可逆性

可逆：把 `record` 的三个分支改回「收到 `failed == 0` 即复位」的布尔折叠即可，但那样就回到「答对一块即清零」。#268 记录了重做触发条件（比例门槛造成误伤时调 `PEARSS_MODEL_FAILURE_RATIO`，而不是回到旧折叠）。
