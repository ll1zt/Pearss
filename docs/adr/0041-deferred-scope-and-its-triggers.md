# ADR 0041：范围裁决——A6 OPML 与 P3 剩余项有意不做，附触发条件

- 状态：accepted
- 日期：2026-09-29
- 相关：ADR 0004（真实客户端优先）、ADR 0016（公开 RSS 输出移除）、ADR 0024（订阅写端点）、ADR 0038（单租户范围）、architecture-spec §5 / §6

## 背景

`architecture-spec.md` §5 的 P3 行与 §6 的追踪矩阵里，还有几项既没有实现、也没有
issue 承载：A6（OPML 导入/导出）、C3（enclosure 音频 feed）、TTS、MCP 拆分、
Gateway、按需 PostgreSQL/Dramatiq/MinIO。P1 行也仍把 OPML 与
`create_feed`/FeedOut CRUD 列为「未完成」。

不落结论的代价是具体的：这些项会以「不知道算不算欠账」的形态长期存在，而下一次
排查的人（或 agent）要么把同一份评估重做一遍，要么把它们当成已决定的欠账。本 ADR
把裁决一次写下，并给每一项一个**重新评估的触发条件**——沿用的正是 ADR 0004 让
Reader API 提前、ADR 0018/0030 让处理器链分段落地的同一条判断方式：**有真实
客户端或真实需求时才做，且有据可查**。

## 决策

### 1. A6（OPML 导入/导出）：不做

理由：本仓库的 Reader 面只服务 NetNewsWire 的 FreshRSS 账号，而那个账号在这个面上
是**只读**的（ADR 0024 的订阅写端点是为 Read You 加的，那是唯一会写的客户端）。
OPML 的用途是**批量迁移**：没有客户端会发它，也没有第二个客户端要导入。批量形态
本身也不缺——`POST /v1/sources` 与 MCP 的写工具已覆盖逐条建源，OPML 只是它的一个
循环外壳。

触发条件（任一成立即重估）：换用会做 OPML 导入/导出的客户端；或出现一次真实的
订阅清单迁移需求；或第二个客户端要导入。

### 2. C3（enclosure 音频 feed）：不做

理由：C1 的公开 RSS 输出已由 ADR 0016 移除，内容消费收敛到 Reader API。音频 feed
会让 `rss_out` 模块复活，并且要重新回答「这个 feed 谁能读」——而 ADR 0016 的结论
是无鉴权 feed 不能上公网。没有订阅者时，它是一段只有维护成本、没有使用者的输出
路径。

触发条件：出现真实订阅者（播客类源 + 一个会订阅音频 feed 的客户端）。

### 3. TTS：不做

理由：TTS 需要一个外部引擎或付费 API，即一个新凭据加一条新出网边界，正好落在
AGENTS.md「首次真实使用检查单」的三问上。它解决的需求（在路上听文章）目前由
客户端侧的朗读能力覆盖。

触发条件：出现「把正文变成音频」的真实场景，且该场景不是客户端朗读能满足的。

### 4. MCP 拆分、Gateway：不做

理由与 ADR 0038 同源：当前是单用户、单入口、单进程，MCP 面是一个进程里的一个
端点。拆分与网关都是**为第二个什么东西**准备的结构（第二个 host、第二个用户、
第二种传输），而 ADR 0038 已经把「第二个东西出现时再断言该假设」写成触发条件。

工具面本身不因此冻结：ADR 0036 已定工具面是 /v1 的语义投影，工具预算工作
（issue #73）也做过一轮压缩。

触发条件：按 ADR 0038——出现第二个用户或 host；或 MCP 传输要做成独立部署单元。

### 5. 按需 PostgreSQL / Dramatiq / MinIO：不做

理由：SQLite 加单进程调度器在当前规模下不是瓶颈，而这三样各是一次**运维形态**
变化（凭据、备份语义、部署单元）。ADR 0009 已把调度器定为「下次抓取时间从 policy
与历史推导、不落库」，规模变化时它仍是可替换的。

触发条件：出现**可测量**的瓶颈（并发写冲突、单进程调度吞吐、附件体积），且该瓶颈
有测量数据而不是预判。

## 后果

- §6 追踪矩阵里 A6 / C3 标为「有意不做（本 ADR）」；
- 这些项不再是「不知道算不算欠账」：每项都有一个可判定的触发条件；
- 代价：触发条件成立前，覆盖度确实比 spec 原文设想的窄——这是有意选择，方向与
  §1.3 非目标一致。

## 附：一处文档与实现的冲突（本 ADR 一并更正）

§5 / §6 里三处标记与当前代码不符。按 AGENTS.md「不要静默选择其一」，记录在此并
更正文档：

1. **B4（处理插件）**标 P3 未做——实际翻译（ADR 0018 / 0030 / 0031）、fulltext、
   embedding（ADR 0035 / 0040，issue #82）均已交付；
2. **C5** 注「P3 处理器链联动待做」——处理器链完成即开闸已实现（issue #82 的
   `_open_gate_if_complete`，由 `tests/integration/test_gate_with_model_identities.py`
   钉住）；
3. **P1 行**仍列 `create_feed` / FeedOut CRUD 为未完成——公开 RSS 输出已由
   ADR 0016 移除，该项随之失去对象。
