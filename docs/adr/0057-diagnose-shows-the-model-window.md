# ADR 0057：`:diagnose` 的模型健康格增窗口计数——「长期半坏」必须在诊断面可见

- 状态：accepted
- 日期：2026-10-05
- issue：#269（本 ADR 是 #269 的交付物）
- 相关 / 修订：**部分 supersede** [ADR 0051](0051-diagnose-projects-the-model-registry.md) 的决策 2「只报当前在冷却的模型」——`models` 那一格仍只报冷却，但新增的 `window` 一格报窗口内失败过的模型（含不在冷却的）。ADR 0051 的其余决策（只读投影、不落库/不缓存、`preferred` 从首见顺序推导、时间一律相对秒、暴露面边界）不变。[ADR 0056](0056-model-demotion-follows-a-rows-failure-share.md) 是判定规则，本条只是它的可见性。

**场景**：AC-259..261（见 `SCENARIOS.md`，归属 #269）。

## 背景

#268 的现场是一个**矛盾**：同一个进程、同一个 10 小时窗口内，journal 有 **132 次** `translate model … falling back to …`，而 `:diagnose` 的 `model_health` 读起来**完全健康**（`skipped: []`、`models: {}`）。

原因是投影的表达力：`models` 只能表达「此刻有两三个模型正在冷却」（#231 的形状）。而那个主模型是**时好时坏**——它每行答对一部分、超时一部分，按 ADR 0056 的降权门槛（比例 ≥ 0.5）**从不进入冷却**。于是它在 `models` 里永远不出现，运维按诊断面判断就会得出相反的结论（本次正是如此：先看到 `skipped: []`，翻 journal 才发现 132 次切换）。

对照 `chain` 那一格报的是**累积量**（queued / succeeded / failed），模型维度却只有**瞬时量**。

## 决策

1. `:diagnose` 的 `model_health` 增一格 **`window`**：按模型折叠**最近 10 行**（`HEALTH_WINDOW_SAMPLES`）里被问过的样本，报 `attempts`（窗口内被问次数）、`failures`、`fallbacks`（窗口内失败过的**行数**——链从它移开的次数）、`failure_rate`（failures/attempts）、`last_failure_class`、`since_last_failure_seconds`。
2. **只报窗口内失败过的模型**：从未失败的模型不出现（无噪音）。「没有这一格」与「有这一格但 failures 为 0」对运维是同一个答案，所以选信息量更小、响应更小的那个。
3. **与 `models` 并存，不替代**：`models` 回答「此刻谁在冷却、冷却多久」（#231 不回归），`window` 回答「最近这条链一直在从谁那里退开」（#269）。两格一起看才是「这条链为什么慢」。
4. **只读投影不变**：仍是 worker 内存登记表的只读投影，不落库、不缓存（ADR 0009/0048/0051）。窗口本身也只是**登记表里的一个环形缓冲**（每模型 10 个样本），不是第二个事实源。
5. **窗口长度是常量，不是旋钮**：改它改变的是运维读到的东西，不是链的行为；给它一个环境变量会让人以为它在调行为。

## 理由

- **诊断面必须能表达「半坏」**。ADR 0056 让「每行部分失败」不再进入冷却（这是有意的：抖动不该拉黑模型），代价就是这类模型**只在累积量上显形**。没有 `window`，`model_health` 会把「慢性半坏」报成健康——比不报更糟，因为它给出的是**相反**的结论。
- **窗口而非计数器**：只有最近 N 行的趋势才对「现在这条链是不是在退化」有意义；一个永不衰减的计数器会把一周前的故障当成现状。
- **`fallbacks` 用行数而不是失败次数**：运维读的是「链从它那里移开了几次」，与 journal 的 `falling back to` 行数同量纲。
- **备选被否决**：
  - **扩大 `models` 的含义（把不在冷却的失败模型也放进去）**：会让「此刻在冷却」这个问题的答案变模糊——#231 的用例依赖 `skipped`/`models` 只含冷却模型。
  - **单独开 `/v1/models:health` 端点**：与 `:diagnose` 是同一个问题，拆开就要调用方自己拼（ADR 0036 的规则，ADR 0051 已否决过一次）。
  - **从 journal 文本反推**：字符串解析脆弱，且成功路径没有日志行（ADR 0048「被否决」表已否决该路径）。

## 后果

- 「这条链为什么慢」现在能在一次调用里区分三种形状：**当下在冷却**（`models`）、**最近一直在退开**（`window`）、**什么都没发生**（两格都空）。
- `model_health` 的响应大小仍是 O(模型数 × 常数)，不随条目数增长。
- 重启后两格都是空的——登记表可丢（ADR 0048 已记录），空不是缺陷。
- 暴露面不变：只有模型名（provider 的模型 id，不是凭据）与错误类别，落在 ADR 0042 的归因字段边界内。
