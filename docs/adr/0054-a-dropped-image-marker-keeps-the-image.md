# ADR 0054：provider 丢掉的 void 标记——内容类（`img`）保留，排版类（`br`/`wbr`/`hr`）丢弃

- 状态：accepted
- 日期：2026-10-04
- issue：#265（本 ADR 是 #265 的交付物）
- 相关 / 修订：**部分 supersede** [ADR 0031](0031-translation-structure.md) 第 47 条——「provider 丢弃/重复/不配对标记时，丢弃该标记而不猜」对**成对**标记与**排版类** void 仍然有效，对 `img` 不再适用；[#150](0031-translation-structure.md) 引入的 void 标记机制（单向标记 + 空闭标签区分）不变

**场景**：AC-255（已登记在 `SCENARIOS.md`，归属 #265）。AC-146 钉住的 `br` 行为不变。

## 背景

ADR 0031 §47 定下：provider 丢了标记就丢那个标记，不猜位置——理由是「放错位置的标签比少一个标签更糟」。AC-146 把这条钉在 `<br>` 上：模型回 `line1line2` 时产物是 `<p>line1line2</p>`，断行没了，文字在。

这条规则把**所有** void 元素一视同仁（#150 的降级说明同样写作「少一个换行/图片」）。但两类 void 的损失性质不同：

- `br`/`wbr`/`hr`：排版。丢了 = 少一个换行或分隔，文字与信息完整。
- `img`：**内容**。丢了 = 读者要看的图没了，且产物里没有任何痕迹说明它曾经在。

实测（伪造 provider 回一个不含 `[[0]]` 的译文）：`<p>See <img src="x.png"/> above</p>` → `<p>看上面</p>`。图被删。这正是 AC-145 抱怨过的形状（「图没了，链接还在」）在**模型丢标记**这一支上的重演。

现实触发路径是「有正文、含内联图片」的块（被引推文 `<a><img></a>`、带插图的段落）：#264 修好了「只有图片的块被发送」这一支，但模型在译文中丢掉 `img` 标记时图仍会消失。

## 决策

**丢掉的 `img` 标记：把元素追加到该块译文的末尾**，而不是连元素一起丢。`br`/`wbr`/`hr` 维持 ADR 0031 §47：丢标记 = 丢那个排版元素。

判定依据仍是 `shells` 表：void shell 的空闭标签是它与成对标记的唯一区分（#150）。已发出的 void shell 记账一次，**已保留的标记不重复追加**（provider 若给 void 标记补了闭标签，同样记作已发出）。

## 理由

- **位置不可知，但「不存在」是确定的损失**。provider 已把标记周围的话译走，追加位置无从推断；而丢图是**静默**的数据丢失——读者和运行者都不会知道少了什么。
- **追加到块尾不切断句子**。void 元素没有文字，放在块尾既不破坏句子结构，也留在同一个块内（块级阅读顺序不变）。
- **只对 `img`**。对 `br` 也追加会把断行挪到句尾，并把「模型丢 `br` 标记」这个**常见**情况（collector 把推文的 `\n` 换成 `<br/>`）从「少一个换行」升级为「多一个尾随断行」——得不偿失。所以按「内容 / 排版」分开。
- **备选被否决**：
  - 「丢掉的 `img` 就让整块保留原文」：不猜位置、不丢内容，但一个丢掉的标记就把整块退回未翻译；`br` 常见，退回的代价更大。
  - 「按标记在原句中的位置插回」：provider 已把周围文本译走，无法定位。
  - 「一律丢弃（现状）」：ADR 0031 §47 的字面执行——正是本 ADR 要修的静默内容丢失。

## 后果

- 产物里可能出现「译文 + 块尾一张图」。位置与原文不同，但内容不丢；这是有意的取舍，记录于此。
- 已保留的标记不重复追加；`br`/`wbr`/`hr` 的行为逐字不变（AC-146 仍绿）。
- 追加的 `<img>` 与其它块内图片走同一条净化与 `_absolutise` 路径（相对 `src` 照常绝对化）：它在 `_restore_inline` 阶段进入产物，而净化与绝对化都在其后。

## 可逆性

可逆：删掉 `_restore_inline` 末尾的追加循环即回到 ADR 0031 §47 的字面行为。产物是派生数据，重跑处理链即可重建。
